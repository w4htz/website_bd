# Отчет по практической работе №1: Контейнеризация веб-приложения на .NET 8 и СУБД PostgreSQL

---

## 1. Цель работы
Изучить основы контейнеризации веб-приложений, настроить оркестрацию многоконтейнерной среды с помощью Docker Compose, а также реализовать слой взаимодействия с СУБД PostgreSQL через библиотеку Npgsql (ADO.NET) на платформе .NET 8.

---

## 2. Что было сделано в ходе работы:

### Архитектура и среда разработки (VS Code)
1. **Организована структура проекта:** В среде разработки VS Code была развернута стандартная MVC-архитектура веб-приложения. Созданы папки для контроллеров (`Controllers`), моделей данных (`Models`), логики работы с БД (`Data`) и интерфейса (`Views`).
2. **Конфигурация проекта:** Создан файл проекта `AutoPartsApp.csproj`, в котором подключена официальная пакетная зависимость `Npgsql` для прямой работы с СУБД PostgreSQL без использования тяжелых ORM.

### Реализация кода приложения (C# / Razor)
3. **Модель данных (`Models/Part.cs`):** Описана сущность автозапчасти со всеми необходимыми свойствами (идентификатор, название, артикул, производитель, цена, остаток на складе и описание).
4. **Бизнес-логика каталога (`Controllers/PartsController.cs`):** Написан контроллер, обрабатывающий отображение главной страницы каталога, просмотр детальной карточки товара, добавление новой позиции через форму, а также POST-метод для покупки товара (уменьшения остатка).
5. **Пользовательский интерфейс (`Views/Parts/`):** На языке Razor сверстаны адаптивные HTML-страницы каталога (`Index.cshtml`), детальной информации (`Details.cshtml`) и форма добавления запчасти в базу (`Create.cshtml`).

### Реализация слоя Базы Данных (`Data/DbHelper.cs`)
6. **Автоматическая инициализация таблицы:** Написан метод `Initialize()`, который при старте контейнера автоматически проверяет наличие таблицы `parts` в PostgreSQL и создает её, если она отсутствует.
7. **Начальное заполнение (Data Seeding):** Реализована проверка на пустоту базы данных. При первом запуске в таблицу атомарно вставляются три стартовых товара (Тормозная колодка, Масляный фильтр, Свеча зажигания).
8. **Безопасные SQL-запросы:** Все методы (`GetAllParts`, `GetPartById`, `AddPart`) написаны с использованием параметризированных запросов (`Parameters.AddWithValue`) для полной защиты от SQL-инъекций.
9. **Конкурентное списание остатков:** Метод `DecreaseStock` обновляет количество товара на складе прямо на стороне СУБД с условием `WHERE stock >= @qty`, предотвращая уход остатков в минус при одновременных покупках.

### Контейнеризация и оркестрация (Docker & Docker Compose)
10. **Многоэтапный Dockerfile:** Настроен файл сборки `Dockerfile` с разделением на два этапа:
    * *Stage 1 (Build):* Использование тяжелого образа `dotnet/sdk:8.0` для компиляции и публикации исходного кода.
    * *Stage 2 (Runtime):* Копирование скомпилированного бинарника в легковесный образ `dotnet/aspnet:8.0`, что гарантирует минимальный размер итогового контейнера.
11. **Многоконтейнерная конфигурация (`docker-compose.yml`):** Описана структура из двух связанных сервисов:
    * Сервис `db` (PostgreSQL 16) с настроенным механизмом `healthcheck` (проверка готовности порта) и `volumes` для персистентного хранения данных на хост-машине.
    * Сервис `web` (веб-приложение), зависящий от успешного прохождения проверки базы данных (`condition: service_healthy`).
12. **Отказоустойчивость подключения:** В точке входа `Program.cs` реализован цикл ожидания СУБД с 10 повторными попытками подключения. Если контейнер базы данных запускается дольше приложения, сайт не падает по таймауту, а дожидается доступности порта PostgreSQL.

---

## 3. Результаты работы
Приложение успешно разворачивается из исходного кода одной командой `docker compose up --build`. Веб-интерфейс стабильно работает по адресу `http://localhost:8080`, обеспечивая сквозную интеграцию пользовательского интерфейса, контроллеров .NET и реляционной базы данных внутри изолированных Docker-контейнеров.
